# 병목별 구현과 사용법

| 기존 병목 | 구현한 대응 | 사용자가 하는 일 | 범위와 한계 |
| --- | --- | --- | --- |
| 매번 모든 자료를 넣어 토큰 소모 | 프로젝트 인덱스, 범위 제한 키워드 검색, 선택된 카드만 읽는 스킬 | 그룹·고객·목표를 말하고 질문 | 절감률은 측정하지 않음. 의미 검색은 미도입 |
| 대화가 길어지면 품질·맥락 유지 어려움 | 상태 파일과 체크포인트로 핵심만 전달하고 새 채팅 생성 | 이어가기 안내에서 선택 | 전체 문장 자동 기억이 아님. 기록하지 않은 세부 내용은 원본 조회 필요 |
| 페르소나가 흐려지거나 불필요한 토론 | 15개 개별 카드·스킬, 단독 호명 준수, 최대 5개 활성 관점 | 원하는 인물/관점을 호명 | 파인튜닝이 아님. 대표 사례를 통한 품질 검수 필요 |
| 서로 다른 고객의 요구사항이 섞임 | 고객별 brief/state/decisions/sources/outputs와 scope 검사 | 고객·산출물을 구분해 시작 | 과거 대화는 미분류이므로 현재 고객 근거로 쓰기 전 확인 |
| 수정·결정이 다음 채팅에서 사라짐 | 주요 단계마다 상태·결정·교정 저장, 인계 무결성 검증 | 중요한 교정/결정을 명확히 말함 | 파일 저장은 스킬 절차. 모든 발화를 자동 확정하지 않음 |
| 근거와 AI 추정이 뒤섞임 | 출처·줄 번호·대화 UUID/메시지 번호, 승인/추정 구분 | 필요하면 근거 확인 요청 | 수입 자료 자체의 사실성을 자동 검증하지 않음 |
| 언제 새 창으로 넘어갈지 모름 | 최근 입력량 추정치가 기준 이상이면 안내, 단계별 인계, 압축 직전 훅 | 안내에서 이어가기/유지 선택 | 정확히 75%인 순간이나 정확한 앱 점유율을 보장하지 않음 |
| 답변의 후속 요청 버튼이 안 눌림 | 선택형 입력 안내창과 앱 채팅 도구 연결, 수동 인계 문구 대안 | 선택지를 제출 | 앱 도구 제공 여부와 훅 신뢰는 대상 PC 확인 필요 |
| 다른 PC에서 처음부터 설정해야 함 | 저장소에 초기 자료 포함, setup이 자동 복원·스킬 생성·경로 재설정 | 저장소 다운로드 후 README대로 설치 | Codex 로그인·프로젝트 열기·훅 신뢰는 사용자 단계 |
| 저장소 삭제 후 사용이 중단될 우려 | 코드·데이터·스킬을 로컬에 보존하고 백업 ZIP 지원 | 설치 확인 후 필요에 따라 저장소 삭제 | PC 간 자동 동기화는 없으며 별도 백업 필요 |

첫 구현에는 외부 MCP 서버, 벡터 DB, 파인튜닝을 추가하지 않았다. Codex 앱의 도구·스킬과 Python 표준 라이브러리만으로 필요한 흐름을 구성했다.

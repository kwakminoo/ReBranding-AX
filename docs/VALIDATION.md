# 검증 기록과 대상 PC 확인

2026-10-31, Windows / Python 3.13.7. 실측과 모의 입력을 구분한다.

## 자동 검사

`python -m unittest discover -s tests -v`로 실행한다. Python 표준 라이브러리만 필요하다.

- 원본 불변, 4개 그룹 분리, 반복 가져오기, 선택적 페르소나 생성.
- 다른 고객 자료 미노출 및 scope 불일치 거부.
- 인계 필수 항목/산출물 존재, 원문 상태 보존, 변조 감지, 목적지 충돌 거부.
- 설치 재실행 시 고객 상태 보존, 기존 훅 설정 충돌 시 보존.
- 비공개 ZIP 복원, 체크섬 오류·경로 이탈·기존 파일 충돌 거부.
- 모의 세션 사용량 74%→76.8%, 오래된 값, 없는 세션, 유지 선택 후 재알림 억제 및 압축 후 재활성화.
- 훅 JSON 출력 계약과 ‘압축 전 경고가 저장 완료는 아님’ 검증.
- 공개 Git index의 경로 allowlist·토큰 형태 검출.

훅의 모의 입력 검사는 실제 앱의 자동 UI 표시를 대신하지 않는다. 의미 검색·사실성·장기 답변 품질 테스트도 아니다.

## 실제 자료·앱에서의 확인

제공된 로컬 자료를 가져와 4개 프로젝트, 185개 문서/과거 대화 검색 항목, 15개 개별 페르소나 카드, 17개 설치 스킬을 확인했다. 원본 JSON은 보존하고 공개 저장소에는 포함하지 않는다. 키워드 검색과 현재 채팅 사용량 읽기를 실행했다.

실제 비공개 데이터 212개 파일을 ZIP으로 묶고, 같은 Windows PC의 비어 있는 다른 폴더에 Windows PowerShell 5.1 설치 스크립트로 복원했다. index 바이트 일치, 185개 항목, 15개 페르소나, 17개 스킬, 누락 파일 없음, 새로운 절대경로의 훅 생성까지 확인했다. Python이 이미 설치된 환경의 시험이며 새 PC의 Python 자동 다운로드 경로는 실행하지 않았다. 실제 물리적인 두 번째 PC의 앱 검증과 구분한다. 17개 스킬의 frontmatter 검증도 통과했다.

구현 전 동일 계정의 앱에서 실제 새 채팅에 짧은 인계 파일을 전달했고 환경·제약·이전 결정·미확인 항목을 구분하는 답변을 확인했다. 사용자가 선택형 안내창에서 기존 시험 채팅 이어가기를 선택한 뒤 메시지 전달·화면 전환·응답 완료까지 도구 결과와 사용자 보고로 확인했다. 후속 요청 chip은 한 차례 입력란 채우기가 확인됐으나 이후 클릭 불가 보고가 있어 유일한 경로로 사용하지 않는다.

이는 앱 도구의 실측이다. 이번 패키지의 완성된 스킬을 새 PC에서 사용한 전체 실행은 대상 PC에서 아래 항목을 확인해야 한다. 사용자의 실제 기존 페르소나 15명 각각의 긴 대화 품질을 자동 합격으로 처리하지 않는다.

## 대상 PC 설치 후

1. README 명령으로 비공개 ZIP 복원. doctor의 ready/missing_sources와 스킬 목록 확인.
2. `anima`와 `writers`의 같은 키워드를 각각 검색해 범위가 섞이지 않는지 확인.
3. 시험 고객을 만들고 서로 다른 조건을 저장. 다른 고객으로 전환했을 때 잘못 가져오지 않는지 확인.
4. 한 페르소나만 호명해 다른 관점을 임의로 추가하지 않고 원문을 참조하는지 확인.
5. 실제 상태를 저장한 뒤 선택형 안내창으로 새 채팅 생성/인계/열기를 진행. 도구가 없으면 복사 문구로 수동 새 채팅 시험.
6. 훅 사용 시 정의를 신뢰하고 다음 사용자 턴에서 실행 여부 확인. 높은 사용량을 만들기 위해 토큰을 억지로 소비하지 않는다. 실제 임계값 안내는 자연스러운 도달 시 관측한다.

고객/페르소나 품질의 대표 질문: 없는 단계가 있다고 가정한 질문에 원문을 확인하는가, 두 고객의 제외 조건을 혼동하지 않는가, 이미 폐기된 결정을 최신 결정으로 가져오지 않는가, 답변 교정을 다음 채팅에도 유지하는가. 실패한 실제 사례를 clients의 출처/결정에 보존해 개선한다.

## 구현의 의도적 한계

사용량은 내부 로컬 로그의 마지막 입력 기준이며 로그 형식은 변경될 수 있다. 훅 신뢰 및 네이티브 도구 제공 여부는 Codex 버전·계정 환경에 달려 있다. 스킬의 작업 단계 저장과 수동 인계는 이러한 기능 없이도 사용 가능하다.

대화 생성은 앱 도구에 맡기며 Python이 비공개 앱 API를 호출하지 않는다. 생성 후 ID를 저장하기 전에 프로세스가 끊기면 자동으로 중복 재시도하지 않고 기존 생성 결과를 먼저 확인한다. 체크포인트는 완전한 트랜잭션형 채팅 API의 대체물이 아니다.

private ZIP의 체크섬은 전송 오류를 찾기 위한 것이며 암호화나 서명은 아니다. 가져온 내용은 자료로 취급하고 임의 명령을 실행하지 않는다. 원본의 경력·통계·학설은 가져오기만으로 사실 검증되지 않는다.
